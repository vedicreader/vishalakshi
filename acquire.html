acquire

Fetch web pages, papers, videos, files, code and JSON APIs into the vault, once or on a schedule

Most methods here fetch content with fossick and file the result with Vault.add. The meta of each document records its source URL and the fetch time. A document found by web also records the query that found it.

source

def clip(
    s:str, n:int=120
)->str:

Collapse the whitespace in a scraped title and cut it to n characters.

url reads one page and converts it to markdown. Many sites answer a script with a challenge page, called a bot wall, instead of the article. With auto=True, the default, fossick then tries a heavier fetcher, then a stealthy browser, then your logged-in Chrome.

crawl follows links from a start page and files each page it reaches. It skips a page whose markdown is empty.

web runs a web search, reads the top n results and files them. It stores the query in the meta of each document. The dropped key of the result lists the results it could not read.

Routing: what a target is

grab(target) identifies the target and calls the method that reads it.

Target Method
arXiv id or link arxiv
YouTube link youtube (transcript and metadata)
GitHub repository github
One file on GitHub gh_file
PDF pdf
Local file, including a Sanskrit file add_file
Directory add_tree
Any other web address url

grab does not file a source file on GitHub as a document. It clones the repository and indexes it with kosha as code.

With crawl=True, grab calls crawl on the target whatever its kind. With shelf=, grab files the result on that named shelf. Without it, grab uses the shelf that KIND_SHELF names for the kind of the target.

Vault.arxiv

def arxiv(
    id_or_url:str, save_dir:str=None, force:bool=False, stop:NoneType=None, progress:NoneType=None, # as in `url`
    **kw
)->dict:

File an arXiv paper, with its metadata and full text, as kind arxiv on the papers shelf.

A directory usually holds two kinds of file. add_dir files prose, such as Markdown, notebooks and PDFs, in the vault. index_code sends source code to kosha, a separate index built for code. add_tree does both, and grab calls it for a directory.

If kosha fails, add_tree issues a warning and leaves the source files out. It does not file them as prose. connect=True runs connect once at the end. It does not run if stop cancelled the ingest or if nothing was filed.

You can stop a long ingest. add_tree, add_dir and add_files take two callbacks.

Argument When it is called
stop Before each batch of batch files (50), before each file in a batch, and before kosha.
progress As progress(done, total, batch) after each batch.

When stop() returns True, the files already filed stay in the vault. The result has cancelled set and unread lists the files not reached. No exception is raised. A fetch already under way finishes.

The other methods take stop and progress too. grab accepts both for any target.

Method When it asks stop
github Before the clone. It then passes both arguments to add_tree.
url, arxiv, youtube, pdf, gh_file, add_file Before the fetch or read.
crawl, web Before the first fetch and between the pages they file.

Without stop, the results of add_tree and web have no cancelled or unread key.

Vault.add_tree

def add_tree(
    dir:str, # tree to ingest
    types:str='.pdf,.md,.markdown,.txt,.rst,.ipynb,.xml,.tei,.htm,.html,.conllu', # extensions filed into the vault as prose
    code:bool=True, # index source files with kosha, when the tree has any
    kind:str=None, # override the kind for the prose half
    connect:bool=False, # rebuild the topic nodes at the end, unless `stop` cancelled the ingest
    verbose:bool=False, queue:bool=False, # enqueue the work instead of doing it; `poll` or `drain` runs it
    batch:int=50, # files per job when queueing, and per batch filed when `stop` or `progress` is given
    stop:NoneType=None, # asked between batches and before kosha; True stops, and `unread` holds the files not reached
    progress:NoneType=None, # told `progress(done, total, batch)` after each batch of documents
    **kw
)->fastcore.basics.AttrDict: # forwarded to add_file

Add the documents in a directory to the vault and its source code to kosha. With queue=True, queue the work instead.

Fanning an ingest out

A large tree can take hours. add_tree(..., queue=True) puts the work on the vault’s job queue (see jobs) instead of doing it. A crash then costs only the batch in flight.

Job Count
Ingest of batch files (50) One per batch
Code indexing with kosha One, when the tree has source files
connect One, with connect=True. It waits until every ingest job has run.

Nothing runs until something runs the queue, such as poll or vault.q.drain(). jobs(kind='ingest') shows the jobs that remain.

The vault skips a file it already holds, so running a batch twice does no harm. A retried batch files only the files it missed. Queueing a batch that is still waiting adds no second job.

Harvest: read a page’s API, not its HTML

Many sites, shops in particular, fill a page with data from a JSON API that the page calls in the background. Reading that API gives clean records instead of scraped HTML.

apis(url) loads the page and captures the JSON calls it makes. It lists them with the number of records in each.

harvest(url) replays one captured call. It runs apis first, unless you pass capture= and the Vault object holds an earlier apis result. capture= is the n of a call in that result. Without capture=, it picks the call with the most records. It follows the pagination of the call when pages is more than 1. It files the records as one document of kind data, with one section per record.

add_records files a list of dicts you already have, from any API or export, in the same way.

Watches

A watch repeats an acquisition on a schedule. watch(target, action=..., every='6h') registers one. ACTIONS lists the actions, and kind= is another name for action.

Action What each run does
url Re-reads a page.
web Re-runs a web search.
harvest Re-harvests an API.
arxiv, youtube Re-reads a paper or a video.
crawl Re-crawls a site.
path Calls grab on a path.
folder Reports changes in a folder.
remind Writes a reminder note.

every takes an interval such as '30m', '1d' or '1w'. cron= takes a five-field cron expression instead. Other keyword arguments go to the action, such as n=5 for a web search.

The clock is pobblebonk, which keeps its schedules in the vault file. poll() is the tick to call from cron, a scheduler or an app’s timer. Each call does these steps in order:

  1. It returns jobs whose worker died to the queue.
  2. It queues a job for every watch that is due.
  3. It runs the queue.
  4. It runs connect if any job succeeded and connect=True.
  5. It runs housekeep if 600 seconds have passed since the last run on this connection.

A failed fetch, or one that hit a bot wall, is retried after a growing delay. After 5 attempts the job is dead. jobs(state='dead') lists dead jobs, and retry_job puts one back on the queue. A worker killed in the middle of a fetch loses its claim on the job, called its lease. The job itself goes back on the queue.

The next run is counted from when the last run was due. A slow fetch does not push later runs back. After a gap, such as a laptop asleep for ten hours under an hourly watch, catchup (1 by default) sets how many missed runs to make up. missed counts the rest. run_watch fires one watch now, outside the queue. pause disables a watch and keeps it. unwatch deletes it. The documents a watch filed stay in both cases.

A folder watch takes a snapshot of the files under a folder, or of those matching pattern. The snapshot holds at most 5000 files. A run reports the files added, changed or removed since the last snapshot. A folder watch needs instructions, the standing brief for whoever reviews the change. Every report includes the instructions. A remind watch writes or updates one note and fetches nothing.

housekeep marks a document stale in these cases:

Source Stale when
Local file The file was deleted, or changed after it was filed.
Web page 30 days have passed and no watch refreshes it.
Video 90 days have passed and no watch refreshes it.
Data harvest 7 days have passed and no watch refreshes it.

Where a watch has filed several copies of one source, housekeep marks the older copies superseded. With prune=True, the default, it deletes the documents that are both stale and superseded.

Images

A photo has no text to search. The vault files what the image file says about itself: its size, the camera, and when and where it was taken (from its EXIF data). It also files any caption or labels you add. labels= holds what an image classifier saw. A search for “galah” then finds a picture of a galah. The pixels stay on disk, and the path key in the meta of the document points at them.

Method What it does
add_image Files one picture as kind image.
add_images Files every picture in a folder.
images Lists the pictures in the vault.
tag_image Adds labels or a caption to a filed picture and rebuilds its searchable text.
