acquire

Fetch web pages, papers, videos, files, code and JSON APIs into the vault, once or on a schedule

Most methods here read something with fossick, the package that does the fetching, and add the result with Vault.add. Each document keeps where it came from in its meta: the URL, when it was fetched, and for a web search the query that found it.

url reads one page and converts it to markdown. Many sites answer a script with a challenge page, a bot wall, instead of the article. Routing: what a target is

grab(target) looks at a target and calls the method that reads it: arxiv for an arXiv id or link, youtube for a YouTube link (its transcript and metadata), github for a repository, gh_file for one file on GitHub, pdf for a PDF, add_file for a local file, add_tree for a directory, and url for any other web address. It is the one call a command line or an agent needs. A source file on GitHub is not filed as a document: its repository is cloned and indexed with kosha as code. crawl=True crawls a web target instead, and shelf= puts the result on a named shelf instead of the one its kind is routed to.

Vault.arxiv

def arxiv(
    id_or_url:str, save_dir:str=None, force:bool=False, stop:NoneType=None, progress:NoneType=None, # as in `url`
    **kw
)->dict:

Read an arXiv paper, its metadata and full text, into the vault as kind arxiv, on the papers shelf.

A directory usually holds two kinds of file. Prose, such as Markdown, notebooks and PDFs, goes into the vault with add_dir. Source code goes to kosha, a separate index built for code, with index_code. add_tree does both, and grab on a directory calls it. If kosha fails, the source files are reported and left out rather than filed as prose. connect=True runs connect once at the end.

A long ingest can be stopped. add_tree, add_dir and add_files take stop, a function asked before each batch of batch files (50), before each file within a batch, and before kosha, and progress, called as progress(done, total, batch) after each batch. When stop() returns True, the files already filed stay in the vault, and the result has cancelled set and unread listing the files it did not reach. Nothing is raised. github asks stop before the clone and then passes both to add_tree. url, arxiv, youtube, pdf, gh_file and add_file ask it before the fetch or read, and crawl and web ask it between the pages they file, so grab takes stop and progress whatever the target. A fetch already under way finishes. Without stop the results are what they were before.

Fanning an ingest out

A large tree can take hours, and a crash should not mean starting again. add_tree(..., queue=True) puts the work on the vault’s job queue (see jobs) instead of doing it: one job per batch files (50), one for the code, and with connect=True one more that waits until every ingest job has run. Nothing happens until something runs the queue, such as poll or vault.q.drain(). A crash then costs only the batch in flight, and jobs(kind='ingest') shows what is left. Running a batch twice does no harm, because the vault skips a file it already holds, so a retried batch does only what it missed. Queueing the same batch again while it still waits adds nothing.

Harvest: read a page’s API, not its HTML

Many sites, shops in particular, fill a page with data from a JSON API that the page calls in the background. Reading that API gives clean records instead of scraped HTML. apis(url) loads the page, captures the JSON calls it makes, and lists them with how many records each one holds. harvest(url) picks the call with the most records, or the one you name with capture=, replays it, follows its pagination when pages is more than 1, and files the records as one document of kind data with one section per record, so each record can be found on its own. add_records files a list of dicts you already have, from any API or export, the same way.

Watches

A watch repeats an acquisition on a schedule: re-read a page, re-run a web search, re-harvest an API, re-read an arXiv paper or a video, re-grab a path, look for changes in a folder, or write you a reminder. watch(target, action=..., every='6h') registers one. every takes an interval such as '30m', '1d' or '1w', and cron= takes a five-field cron expression instead. The actions are listed in ACTIONS, and kind= is another name for action. Other keyword arguments go to the action, such as n=5 for a web search.

The clock is pobblebonk, which keeps its schedules in the vault file. poll() is the tick to call from cron, a scheduler or an app’s timer. Each call returns jobs whose worker died to the queue, queues a job for every watch that is due, runs the queue, runs connect when any job succeeded, and every ten minutes runs housekeep. A failed fetch, or one that hit a bot wall, is retried after a growing delay, and after five attempts the job is dead: jobs(state='dead') lists those and retry_job puts one back. A worker killed in the middle of a fetch loses its claim on the job, its lease, but the job itself goes back on the queue.

The next run is counted from when the last one was due, so a slow fetch does not push later runs back. After a gap, such as a laptop asleep for ten hours under an hourly watch, catchup (1 by default) says how many of the missed runs to make up, and the rest are counted in missed. run_watch fires one watch now, outside the queue. pause and unwatch stop a watch; the documents it already filed stay.

A folder watch takes a snapshot of the files under a folder, or of those matching pattern, and fires with what was added, changed or removed since its last look. It must have instructions, the standing brief for whoever reviews the change, and they come back with every change. A remind watch writes or updates one note instead of fetching anything.

housekeep marks a document stale when its source has moved on: a local file deleted or changed since it was filed, or a web page (after 30 days), video (90 days) or data harvest (7 days) that no watch refreshes. Where a watch has filed several copies of one source, the older ones are marked superseded, and only documents that are both stale and superseded are deleted.

Images

A photo has no text to search, so the vault files what the image file says about itself: its size, the camera, and when and where it was taken (from its EXIF data), with any caption or labels you add. labels= carries what an image classifier saw, so a picture of a galah can be found by searching for “galah”. The pixels stay on disk, and the document’s path points at them. add_image files one picture as kind image, add_images files a folder, images lists them, and tag_image adds labels or a caption later and rebuilds the searchable text.
