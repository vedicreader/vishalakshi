vishalakshi

One vault for everything you read: web pages, papers, videos, files and code, searchable together and answerable by a local or hosted model

vishalakshi keeps what you collect in one SQLite file on your own machine, called a vault, and lets you search it and ask questions of it. One question can draw on a paper, a web page, a talk transcript, your own notes and the source code on disk at once, and the answer cites the sections it used.

It is built from smaller packages. fossick fetches pages, papers and videos. litesearch stores the text and finds it again by keyword and by meaning; a Vault is a litesearch Index, and its search defaults come from there. Urai is the chat interface the vault talks to models through, and Rishi supplies the model backends. kosha indexes source code, and rgapi searches files on disk that nothing has indexed yet. rahasya finds personal information and varga recognises what kind of document something is.

Install

pip install vishalakshi

Adding and searching

Vault() with no argument opens ~/.vishalakshi/vault.db. This page uses a throwaway file and fills it with this repository’s own docs and source.

from tempfile import mkdtemp
from litesearch import repo_root
from vishalakshi import Vault

root = str(repo_root() or Path('..'))   # works from nbs/ or the repo root
v = Vault(Path(mkdtemp())/'vault.db')
v.enc.note
'minishlab/potion-multilingual-128M (256d, float16, model2vec)'

add takes a directory, a file or a piece of text. grab takes almost anything else, such as an arXiv id, a YouTube link, a GitHub repository, a PDF or a web address, and reads each the right way (acquire). Adding a source that is already in the vault reads it again only when its content changed, and the result’s changed says whether it did. note writes your own note. A note with a key= or a title replaces the earlier note with the same key or title; a note with neither is added as a new one.

Every search result carries age, the seconds since its document was filed, and stale, which is True when the vault believes the document no longer matches its source. Stale results sort last. poll() (below) marks documents stale: a file that changed or vanished, a web page past its time limit that no watch refreshes, or an older copy that a watch has replaced. It deletes only documents that are both stale and replaced.

v.add(root)                       # README.md and every notebook under nbs/
v.note('federate fuses the legs by rank because they share no vector space: the vault embeds '
       'prose, kosha embeds identifiers, ripgrep embeds nothing.', tags=['retrieval', 'design'])
v.note('one document per key: writing it again replaces it', title='federation', key='federation')
v.stats()

To answer questions the vault needs a language model. The default is gemma-4-E2B, a small model that runs on this machine through LiteRT, on the GPU where there is one, and needs no API key. model= names any other model Rishi knows, local or hosted, and chat_kw= passes settings to it. $VISHALAKSHI_MODEL changes the default and $VISHALAKSHI_GPU=0 keeps LiteRT on the CPU. ask retrieves the four best sections (sections=4), shows the model up to 1,500 characters of each (max_chars=1500), and returns the answer with cited, the sections the answer cites (ask).

r = v.ask('why are rankings fused instead of distances?')
print(r.model, '·', r.runtime)
print(r.answer)
print(L(r.cited).map(lambda c: f"{c['n']} {c['breadcrumb']}"))
if (hit := first(r.cited)): print(v.read(hit['node_id'])['text'][:400])

Personal information and junk

A personal vault holds things that should not leave your machine: invoices, letters, bank statements. vishalakshi looks for personal information in everything it stores, with patterns and checksums rather than a model: email addresses, phone numbers, card and account numbers, national identity numbers, street addresses, dates of birth and API keys. On a held-out test set of 240 generated documents it missed nothing and raised no false alarm (evals/RESULTS.md). Names are harder. It finds only names that follow a title such as Dr or Mrs, and only when name detection is on (ner=True); a report’s scanned_ner says whether it looked.

What it finds sets each document’s privacy level: Open, Personal (an identifier was found, or someone marked it), or Local only (set by hand, or a sensitive type such as a passport or a payslip). Each shelf can also have a floor, a level none of its documents goes below. Before every model call the vault decides, with send_check, what each document may give a hosted model, meaning one that runs anywhere but this machine: an Open document goes whole, a Personal one masked or not at all, a Local only one never. A document’s title, headings and source path go under the same rule as its text. A model on this machine may read everything. Each send to a hosted model is recorded in the vault’s send log. The details are on pii.

Junk is a separate problem: cookie banners and site footers that match every search and answer nothing. suggest_noisy ranks likely junk without any labels (0.988 AUC on the test corpora) and mark_noisy takes a document out of search (quality).

pii= in ask what happens when the retrieved sections hold personal information
local a model on this machine answers, told never to repeat a personal detail; if the model is not local, nothing is sent
redact each recognised identifier is masked, then the named model answers, hosted or not. The heading, title and source of each section are masked with its text. Names without a title are not masked
refuse no model is asked, and the result says what was held back

The default is local when a local runtime is installed and redact when not. ask cannot run with detection off: pii='off' warns and applies the default. The result’s policy says which was used, and any identifier the model repeats is masked in the answer. Under every policy a hosted model gets a Local only section only as a placeholder, with no heading, title or source. Search and reading take pii= too (off, redact or refuse), and there the default is off, which returns the stored text. The MCP server defaults to redact for every tool and refuses off, since its client is a model the vault does not run.

v.mark_not_pii(doc_id, reason='my own invoice')          # a person clears a false alarm
v.set_level(doc_id, 'local')                              # never send this one to a hosted model
v.send_check(refs=[doc_id], model='gpt-4.1-nano').why     # what a send would do, in one sentence
v.accept_noisy(k=10, reason='reviewed')                   # mark the current top junk suggestions
v.fit_noise(save=True); v.use_noise(True)                 # optional: fit the junk score to your marks

Paperwork

A document’s kind says how it arrived; its doctype says what it is, such as an invoice, a receipt, a contract, a paper or a payslip. categorize decides the doctype from cue phrases and figures in the text, and asks a model only when the cues cannot decide. extract pulls fields out of a document, such as an invoice’s number, vendor and total; without a schema, the doctype picks one. ask_doc, or ask(ref=...), answers a question about named documents, read whole, with the rest of the vault behind them. Code

index_code builds a kosha index of a repository: its functions and classes, their names and the call graph. Once that index exists, context and ask add code sections beside the prose (code=). A code hit has no node_id; it is cited by path:line on disk. grep searches the files on disk with ripgrep and needs no index, and federate merges prose, code and ripgrep results into one ranking.

Watches and the queue

A watch repeats an acquisition on a schedule. Its action is an acquisition method (url, web, harvest, arxiv, youtube, crawl or path), remind to write a note, or folder; kind= is the same thing under another name. A folder watch keeps a snapshot of a directory and fires with what was added, changed or removed, together with its instructions for whoever reviews the change. A schedule is every='6h' or cron='0 9 * * 1', and pobblebonk keeps the schedules in the vault file.

poll() is the tick to call from cron or an app’s timer. It returns jobs whose worker died to the queue, queues the watches that are due, runs the queue, and every ten minutes runs housekeep. A failed fetch is retried with a growing delay and set aside as dead after five attempts; jobs(state='dead') lists those. See jobs.

v.watch('https://example.com/changelog', action='url', every='6h')
v.watch('late chunking retrieval', action='web', every='1d', n=5)
v.watch('Re-read the evals', action='remind', every='1w')
v.watch(Path(root)/'nbs', kind='folder', every='1h', instructions='flag any print() left in a notebook', pattern='*.ipynb')
L(v.watches()).map(lambda w: (w['kind'], w['target'][:34], w['every'], w['pattern']))

Books and scans

A scanned book has no usable text layer, and an old print set in a legacy font may have one that reads as gibberish. read_doc reads a PDF or a page image page by page and picks a route for each page (parse='auto'): a text layer that passes its checks is kept, a scanned page is OCRed, and a page still scanned or flagged as garbled goes to a vision model, local or hosted. preset= picks the reading prompt (generic, sanskrit, tamil or tables), and hint= adds a sentence about the book. Given a folder, it reads every PDF and image under it. Each page’s text, route and flags are kept as numbered versions, so reading a page again with a better model (reparse) never loses the earlier reading. A page image cannot be masked, so a Personal page goes to a hosted model only with allow=True, and a Local only page never does. Readings are recorded and replayed through CachedChat, and a page with no recording yet reaches the model only when $VISHALAKSHI_RECORD_CHAT is set or a chat= is passed (read).

proofread has other models read the pages again and files the word changes each reading would make. A change two readers agree on is proposed, and one that only one reader makes is in doubt. Nothing changes until the owner decides: accept applies changes as a new version of the page, reject sets them aside, and undo_decision and revert_page take decisions back (proof).

v.read_doc('books/', parse='auto', model='claude/sonnet', preset='sanskrit', hint='verses end in ॥ n ॥')
