read

Read PDFs, scans and page images page by page, with a vision model where the text layer cannot be trusted, and keep every reading of every page

Many PDFs carry a text layer, the text you can select and copy. When the PDF was made from a digital document that layer is exact and costs nothing to read. A scanned PDF has no text layer, or one made by OCR (optical character recognition) that may be poor. Old books in Indian scripts are often worse: many were set in legacy fonts whose text layer reads as Latin gibberish, or splits akṣaras, the letter clusters of Devanagari, apart. A vision model, one that reads images, can read such a page from its picture, but it costs time or money for every page and makes mistakes of its own.

read_doc decides page by page, and parse sets the route:

parse= what each page gets
auto, the default a text layer that passes the checks below is kept; a scanned page is OCRed; a page still scanned or flagged after that goes to model
text the text layer only; a scanned page stays empty
ocr OCR on every page
llm model on every page

model is any id Urai knows, local or hosted, such as claude/sonnet or gemini/gemini-2.5-flash; None means $VISHALAKSHI_MODEL. There are two ways in. The function read_doc(path) reads one file and returns its pages, with no vault involved. Vault.read_doc(src) reads a file, or every PDF and image under a folder, into the vault: each file becomes one document, and each page’s text, route and flags are kept as numbered versions, so reading a page again never loses an earlier reading.

Prompts

A vision model is told what to return by a reading prompt. PRESETS holds four. Each asks for the page as JSON: a list of items in reading order, where an item is a heading, a paragraph of prose, a verse, a table, a note or a colophon (the line that closes a chapter in an Indian text), with its text exactly as printed and any number printed with it. Once read, these items are called blocks. generic suits any printed page. sanskrit and tamil name the letters that old prints in those scripts make easy to misread, and sanskrit also tells the model to leave out translation and commentary. tables reads tables as rows of cells.

Every preset also asks for a box per item: the region it covers, as [x0, y0, x1, y1] in fractions of the page’s width and height measured from the top left, so an app can crop the block out of the page image or highlight it.

reading_prompt fills a preset in with the document’s title, its script (Devanagari unless you say otherwise) and a hint, a sentence about this particular book, such as how it numbers its verses or what to skip. A preset that is not one of the four names is used as the whole prompt. If it contains {of}, {title}, {script} or {hint} they are filled in, and a prompt whose JSON braces are not doubled is sent unchanged.

Pages as images

A model is sent a picture of the page. render draws one page of a PDF as a PNG at dpi (200 by default). Some hosted models refuse large images, so when the PNG is over max_bytes (3 MB) render returns a JPEG whose long side fits max_px (3,000 pixels) instead, and fit does the same for an image file. Two cuts help with hard pages. halves splits a landscape image, usually a scan of two facing pages (a spread), into its left and right pages. page_strips cuts a tall page into overlapping horizontal strips, so the model sees worn or small type at a larger scale.

Checks

flags lists what looks wrong with a page’s text. It is how parse='auto' decides that a text layer cannot be trusted.

flag meaning
thin fewer than min_chars (20) letters, as on a scanned page
replacement the Unicode replacement character, which marks text that failed to decode
legacy more than 5 Latin-1 or typographic characters per 100 letters, which is how a legacy Devanagari font’s text layer reads
split a line that starts with a vowel sign or virāma, a piece of an akṣara cut off from the rest
akshara an akṣara that cannot be written, such as a virāma followed by a vowel sign
foreign Greek or Cyrillic letters next to Devanagari

disagree(a, b) measures how far two readings of the same text differ: the letter edits between them divided by the letters in the longer one. Spaces, digits, daṇḍas and punctuation are ignored and vowel signs count. A value of 0.1 or more is worth a look.

Reading a page

read_page sends one page image to a vision model and returns its blocks, their text joined as markdown (text), the model and the cost its backend reported. With no chat=, the call goes through CachedChat, so each reading is recorded once and replayed after that, and reading the same page again costs nothing. The recordings go in chatcache in the working directory, or the folder $VISHALAKSHI_CHAT_CACHE names. A page that has no recording yet reaches the model only when $VISHALAKSHI_RECORD_CHAT is set; otherwise read_page raises an error that says so. fresh=True drops the recorded reply and asks the model again. A reply that is not JSON raises an error and is not recorded, so the next try reaches the model. chat= takes any callable in place of a model, which is how the tests run without one, and every image sent is first held to the size limit by fit.

A block keeps its box only when it is four numbers that make a real rectangle, clamped to the page; any other box is dropped. crop cuts a block out of the page image by its box.

Before sending, read_page asks send_rule whether the page may go, as an image. The page’s level is its document’s level, raised to Personal when text, its text layer or OCR, holds an identifier. A page image cannot be masked, so a Personal page goes to a hosted model only with allow=True or pii='off', and a Local only page never does. A page that may not be sent comes back empty, with blocked saying why.

Reading a document

read_doc(path) takes a PDF or a page image and returns one row per page, {page, text, route, flags}, with blocks, model and cost on a page the model read. route says how the text was got: text (the text layer), ocr, model, or scanned when nothing read the page. pages=[...] limits which pages may go to the model, and the others keep their text layer. Up to workers pages (4) are read at once.

Privacy works page by page, as in read_page. When any page is going to a model, the whole text layer is first checked for a sensitive doctype, so a document whose text reads clearly as a passport or a payslip is Local only before any page image leaves. local_model=, or a built local_chat=, reads the pages that the hosted model may not; without one those pages keep their text layer and carry blocked. A scanned page has no text to check, so it is judged by its document’s level alone.

Long reads need control:

  • progress(done, total, page, route, cost) is called once with done=0, then after each page that was due for the model. Returning False stops the reading. The pages not yet read keep their text layer or OCR, the result’s cancelled is True and unread lists them. An error raised inside progress is ignored.
  • cache= keeps each model reading as a JSON file, {page, items, cost, model}, in a folder (p0001.json, or p0001a.json and p0001b.json for the two halves of a spread) or wherever a function cache(page, half) says. A cached page is not sent again: its cost is None, since nothing was spent, and cached is True.
  • redo=[...] reads those pages again even when cached. Once the new reading is saved, the old one moves to a sibling folder named after the cache folder with _prev added, numbered when an older copy is there already.
  • spread=True treats a landscape page as two facing pages and reads the halves in turn. strips=k sends each image as k overlapping strips.
  • clean= is a function applied to each block’s text before it is kept.
  • tries=n tries a failing page up to n times, waiting RETRY_WAIT seconds (10) after the first failure, 20 after the second, and so on. A page that still fails keeps its text layer, carries its error, and is listed in the result’s failed. Without tries, the first error is raised.

doc_cost(rows) adds up the cost of the pages a model read, and doc_files(folder) lists the PDFs and images under a folder.

Into the vault

Vault.read_doc(src) reads a file, or every PDF and image under a folder, and adds each file to the vault as one document that search and ask can reach like any other. It also keeps each page in the read_pages table as a version. A page gets a new version only when its text, route or blocks changed, so reading a file twice with the same result adds nothing. Each new version is scanned for personal information and its findings are filed against it (see pii). A new document starts at the shelf’s floor, and one already in the vault at its own level. Vault.pages(doc_id) gives the latest version of each page, and history=True gives every version. Every page read by a hosted model is written to the send log. The result is the ingest result with routes (how many pages took each route), flagged, blocked, cost, model_pages, cancelled, unread and failed added.

Vault.reparse(doc_id, pages=[...]) reads pages of a document again, by default with the model (parse='llm') and with the document’s own preset, script and hint, files the new readings as new versions and re-indexes the document. Use it when a page came out badly and a better model should have it. reparse returns the pages it read, those whose text changed, blocked, cost, model_pages, cancelled and unread. Both methods take progress, and a cancelled reparse leaves its unread pages as they were. When a folder is read with cache=, each file caches in its own subfolder, named after the file.
