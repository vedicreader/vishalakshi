ask

Answer questions from the vault with a local or hosted model, cite the sections used, and check what each model is sent

ask answers a question from the vault with a language model. Urai is the chat library that vishalakshi calls. Rishi provides the model backends, and Urai registers them the first time a chat is built.

A model id names the model, and the id selects the backend. The local backends are LiteRT, MLX, llama.cpp and Ollama. A hosted API id looks like claude/sonnet or gpt-4.1-nano.

With no id, the vault uses gemma-4-E2B. This small model runs on this machine through LiteRT and needs no API key. Set $VISHALAKSHI_MODEL to use a different default.

LiteRT is asked for the GPU backend. When no GPU is available, LiteRT uses its default backend and a warning appears. Set $VISHALAKSHI_GPU=0 to keep LiteRT on the CPU.

chat_kw= passes any other chat constructor argument, such as a temperature.

Answering with citations

ask(question) calls context to retrieve the sections of the vault that best match the question. mk_prompt numbers the sections [1], [2] and so on. It also lists the related sections by title only. A related section is a neighbour of a retrieved section in vector similarity. The question does not retrieve it.

The system prompt VAULT_SP tells the model to answer only from the sections and to cite the number of each section it used. ask returns the answer and cited. cited lists the sections that the answer cites. Each entry has a node_id that read opens.

The context budget is sections=4 and max_chars=1500. max_chars is the number of characters kept from each section.

To ask about particular documents, pass ref= with one or more documents, or use ask_doc from extract. doc_context then puts the named documents first, whole, as sections [1] to [n]. The named documents share doc_chars characters. doc_context adds related sections from the rest of the vault after them.

mk_chat= gives ask a chat that the host already runs, such as a model that an app has loaded. ask then builds no new chat. The privacy check reads the runtime of the chat that ask uses. A hosted chat passed by mistake is treated as hosted.

A section is private in three cases. The detector finds personal identifiers in it. Its document is marked as personal. Its document has a level above Open for another reason, such as the document type or the shelf floor.

Before ask sends anything, it drops each related section that holds personal information. When ref= names documents, it also drops each retrieved section that holds personal information. pii= then sets what happens to the remaining sections:

pii= what happens when the sections are private
local A model on this machine answers. The model is pii_model, else $VISHALAKSHI_PII_MODEL, else the default model. It runs under PII_SP, a system prompt that forbids repeating any personal detail. If that chat is not local, ask sends nothing and the answer says so.
redact ask masks the recognised identifiers in the text, heading line, title and source of each section. The model named by model= then answers, hosted or not.
refuse No model is asked. The answer says what was held back.

The default policy is local when a local runtime is installed, and redact when none is. pii='off' is not valid for ask. It gives a warning and applies the default. The policy field of the result names the policy that ran.

Under every policy, a hosted model receives a Local only section as the bare line [n] [withheld: local only]. The line has no heading, title or source. send_check below explains the rule.

Under redact, ask does not mask a name that has no title before it, such as Dr. Name detection is on by default (pii_ner=True).

ask scans each answer over private sections again before it returns the answer. It masks any identifier that the model repeated, and leaked lists the kinds of identifier.

The result also has the prompt and the context that the model read. Under local they hold the private sections whole. A host that gives the result to a hosted model must pass on only answer and cited.

Deciding what a model may be sent

send_check runs before anything goes to a model. For each document, page or piece of text, it decides one of three outcomes: whole, masked, or withheld. Withheld means not sent.

send_check returns the decisions in rows, and the subsets send, masked and withheld. It also returns a why sentence for a person to read before the send. An example is gpt-4.1-nano, hosted. 1 personal document masked, 1 document open, 1 local-only document withheld.

send_rule holds the rule:

  • A model on this machine receives everything whole. model_local decides which models are local. LiteRT, MLX and llama.cpp are always local. Ollama is local only when $OLLAMA_HOST points at this machine. Every other runtime is hosted. A chat that names no runtime is hosted.
  • An Open item goes whole to any model.
  • A Local only item is withheld from a hosted model under every policy. allow=True does not change this.
  • Under redact, a Personal item goes to a hosted model masked. Under local and refuse, it is withheld.
  • A page image cannot be masked. A Personal page image is withheld from a hosted model under every policy except off, and when allow=True.
  • allow=True allows once. It sends Personal items whole for that one call, as policy='off' does.

ask, explain, categorize, extract, read_doc, reparse and proofread all decide through this rule. The decision covers everything that goes with the text. A document’s title, headings and source path are masked or withheld with it. A page image is read with the document’s title in its prompt. send_check judges the title with the page.

build_graph sends every chunk to its chat with nothing to mask. connect calls build_graph. A hosted chat builds the graph only when every document on the shelf is Open. Otherwise build_graph sends nothing and the result says why.

Masking replaces only what the detector recognises. A document marked Personal by hand, with nothing recognisable in it, goes to a hosted model under redact exactly as stored.

The send_log table of the vault records each send to a hosted model. A row has the time, the document and pages, the model and runtime, the policy, and the kinds of personal information when known. sends(ref) reads the log, newest first. The log has no row for a send to a local model or for a withheld item.

Recording what a model said

CachedChat records the replies of a model on disk and plays them back. Tests and these pages use it to show real answers without a model run. The vault treats a CachedChat as any other chat.

The recording folder is path, else $VISHALAKSHI_CHAT_CACHE, else chatcache in the working directory.

A question with no recording raises an error. When $VISHALAKSHI_RECORD_CHAT is set, the question goes to the real model and CachedChat records the reply. The next run answers from disk.

Building a CachedChat registers Rishi’s runtimes, as new_chat does. runtime then names the backend of the id and builds no engine.

The default budget is sections=4 and max_chars=1500. Six sections of 4,000 characters each overflowed the context window of the 2B default model. LiteRT reported this as a send failure with no explanation (evals/RESULTS.md).

When a send fails this way, ask gives a warning and tries once more on a new chat. The second try uses the first two sections, each cut to a third of max_chars, and no related sections.

When the sections hold personal information

pii explains the detector and the marks. The cells below show what ask does with them. They use a stand-in chat that records everything it receives. A leak appears as a recorded call.

The check runs on the chat that ask built, before ask sends anything. The next cell passes a hosted chat under the default local policy. ask does not call the model.

_seen.clear()
r = _v.ask('what is on invoice 4471?', mk_chat=_chat('remote', 'THIS MUST NEVER BE SENT'))
test_eq(_seen, {})                       # the model was never called at all
test_eq(r.refused, True)
r.answer
'held back: these sections hold personal information (card, email, phone) and remote is not a local runtime, so nothing was sent to it'

With a local runtime, ask sends the private sections to the local model under PII_SP. PII_SP tells the model to answer with counts, kinds and totals instead of personal details, and to say what it held back.

_seen.clear()
r = _v.ask('what is on invoice 4471?', mk_chat=_chat('litert',
    'One invoice, 240.00 GBP, due in September. Holding back the name, email, phone and card. '
    'Tell me what you need: a total, a due date, or a yes/no.'))
test_eq(_seen['runtime'], 'litert')
test_eq(_seen['sp'], PII_SP)             # not VAULT_SP: that one tells it to cite, and a citation points at the text
test_eq(r.get('refused', False), False)
r.answer
'One invoice, 240.00 GBP, due in September. Holding back the name, email, phone and card. Tell me what you need: a total, a due date, or a yes/no.'

instruction= sends a follow-up turn. When the local model holds something back, it names an instruction that would let it answer, such as “give me the total and the due date”. The caller sends that instruction with the same question.

_seen.clear()
r = _v.ask('what is on invoice 4471?', instruction='Give me the total and the due date only.',
           mk_chat=_chat('litert', 'Total 240.00 GBP, due 2026-09-01.'))
test_eq('Instruction from the questioner' in _seen['prompt'], True)
r.answer
'Total 240.00 GBP, due 2026-09-01.'

ask scans every answer over private sections again before it returns the answer. It masks identifiers that the model repeated, and leaked lists their kinds.

_seen.clear()
r = _v.ask('what is on invoice 4471?',
           mk_chat=_chat('litert', 'It is for ada@example.com, card 4111 1111 1111 1111.'))
test_eq(r.answer, 'It is for [EMAIL], card [CARD].')
r.leaked
{'email': 1, 'card': 1}

pii='redact' masks the recognised identifiers in the text of each section. A hosted model then answers. A name is masked only when a title such as Dr comes before it. “Ada Lovelace” is not masked, as a real-model cell further down shows.

_seen.clear()
r = _v.ask('what is on invoice 4471?', pii='redact', mk_chat=_chat('remote', 'An invoice for 240.00 GBP [1]'))
test_eq('ada@example.com' in _seen['prompt'], False)
test_eq(_seen['runtime'], 'remote')
r.answer
'An invoice for 240.00 GBP [1]'

ask scrubs the fields of a structured answer (schema=) in the same way. An API key counts as personal information, as an email address does. A hosted chat is refused for a section that holds an API key, and for a document marked by hand.
