core

The vault: one SQLite file that holds everything you have collected, and the search over it

A vault is one SQLite file that holds everything you have collected, such as web pages, papers, talk transcripts, PDFs, notes and source files. All of it is searchable together. Vault() opens the file $VISHALAKSHI_VAULT names, else ~/.vishalakshi/vault.db. Vault(path) opens or creates any other file. Vault(':memory:') makes a vault that lasts only as long as the process.

A Vault is a litesearch Index. litesearch decides how text is stored and found. Each thing you add becomes a document. litesearch splits a document along its headings into a tree of sections, which it calls nodes. It cuts the text of each section into chunks. It stores every chunk twice. One copy is text, for the full-text keyword search of SQLite. The other copy is a vector, a list of numbers from an embedding model. The model puts texts with similar meanings near each other. A search runs both lookups and merges the two rankings with reciprocal rank fusion (RRF). RRF scores each chunk by its rank in each list. It does not use the raw scores, because a keyword score and a vector distance cannot be compared. The default embedding model is potion-multilingual-128M. It is small and fast and covers over 100 languages, including Devanagari. encoder= picks another model (see concepts).

The vault adds these to litesearch:

  • a kind on every document that says how it arrived (web, pdf, arxiv, note, code and so on)
  • shelves that keep separate collections in the same file
  • marks that record the judgements of a person about a document
  • an entity graph and a topic map
  • the methods on the other pages that fetch, read, extract and answer

Add text, pages, a file or a directory to the vault, adding a source again only when its content changed.

search returns chunks. Each hit has a short snippet, the node_id of its section and the doc_id of its document. sections ranks whole sections instead. context returns the text to give a language model. It returns whole sections. Each section has a breadcrumb, the path of headings down to it, such as Attention › Multi-head. Each section also has a node_id, which read turns back into the full section. The related list of context holds sections as leads. They are found by vector similarity to the results, not by matching the question. context also adds two sections from each other shelf (shelves=2). It adds code sections (code=) when kosha has indexed the repository. rerank=True reorders the hits with a cross-encoder model. It needs the rerank extra (pip install 'vishalakshi[rerank]').

These methods, and read and document, take pii=. The default is off. See pii. Every row also has age, the seconds since its document was filed, and stale. Stale rows sort last.

A node_id names a section. A doc_id names a document. doc(ref) finds the row of a document by its id, its exact source, or part of its title. document(ref) rebuilds a whole document in reading order and puts its headings back. A model reads this text to extract fields. Given a path that the vault has never seen, document reads the file from disk. read(node_id) rebuilds one section. toc returns the heading tree of the shelf or of one document.

The meta of a document holds where it came from and anything set with set_meta, such as its doctype. Adding a changed document again rewrites its meta. A lasting judgement about a document goes in the doc_marks table instead (see Marks below).

Shelves

One vault file can hold several shelves. A shelf is a separate collection with its own chunks, section tree and vector index. A large corpus on one shelf, such as a thousand papers, does not crowd a small shelf out of the rankings. shelf(name) opens a shelf and creates it the first time. A shelf keeps the embedding model it was first written with. Reopening it with a different model raises an error, because vectors from two models cannot be compared. shelves() lists the shelves with their models and document counts. drop_shelf deletes a shelf. The main shelf is called store. SHELVES names the shelves that the vault itself uses: store, papers, sanskrit, code and data. Acquisition sends some kinds to their own shelf through KIND_SHELF, below.

Marks

A mark is a judgement about one document. The doc_marks table keeps it when the document is added again. There are three marks. noisy is for junk such as a cookie banner or a site footer. search, sections, context and ask leave noisy documents out. pii_override holds the privacy marks described on pii. stale says that a document no longer matches its source. Search still returns a stale document, flagged and sorted last. The vault clears the mark when the document is added again with new content. mark sets any of them. mark_noisy, mark_stale and the pii methods are the named ways to set a mark. marks() lists every mark on the shelf. marks(ref) returns the mark on one document.

A shelf opened from a vault shares the embedding model of the vault in memory. Opening many shelves loads the model once. offline=True and $VISHALAKSHI_OFFLINE also carry over to a new shelf. An offline vault never downloads a model.

# A shelf is a partition. It reuses the live encoder of the vault and does not load a second encoder.

KIND_SHELF sends documents of some kinds to their own shelf when they are added to the main shelf. arXiv papers go to papers. Sanskrit files go to sanskrit when add_dir finds them and ganapati is installed. search and sections look at one shelf only. context adds results from the other shelves (shelves=). elsewhere(q) searches every other shelf directly. Use it when the answer can be on another shelf.
